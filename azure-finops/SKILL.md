# Azure FinOps plugin maintenance

Read the installed FDO SDK render, safe-authoring, operator and privileged-action contracts before changes. Verify the sibling host implementation when an API is uncertain. No invented SDK methods, generic shell runner, automatic login, access-token command, or direct Azure fetch belongs here.

- Keep demo and live providers behind `Provider`. Demo never emits a privileged action. Use one demo clock for all evidence and relative ages.
- Keep UI and chart rendering in the iframe. Mount host `FDOCharts` in a connected element, dispose on replacement/teardown, and retain data summaries when unavailable.
- Generate Azure CLI argument arrays in the backend using `createScopedProcessExecActionRequest`. The UI is only a transport relay because the installed SDK privileged transport is iframe-only. Host grants and confirmation remain authoritative.
- The default requested custom scope is `azure-finops`. Keep the exact setup instructions and executable/argument/environment/timeout/confirmation policy in Settings and README synchronized with the inspected host. Saving a scope ID never grants it.
- Preserve full tenant/subscription/resource IDs in proposals, reviews, operations and details. Normalize only for joins. Scope changes must discard stale responses, refresh groups and clear invalid selections. Do not assign historical charges to current inventory dimensions.
- Preserve independent creation, creator, owner and provisioning evidence. Earliest retained writes and resource-group age never prove resource creation. First observed is not created at.
- Never combine currencies or cost bases. Missing costs, utilization, forecast or comparison data are unknown, not zero. Do not label newly billed resources when comparison coverage failed.
- Keep proposals durable and non-executing. Reviews are short-lived and single-use. Treat every mutation as dangerous: typed target names for all actions, a disabled execution control until names and acknowledgement match, exact CLI argument preview, bulk acknowledgement, current-state/lock checks and exact-target revalidation are required. Never remove locks, force-detach or delete related resources. Guard VM delete options. Resize requires a deallocated VM, same-family hardware contracts, restrictions/quota checks and fresh revalidation; never silently deallocate or start.
- Record per-target outcomes and treat lost acknowledgements/timeouts as unknown. CLI termination/polling cancellation is not proof an Azure operation was cancelled. No mutation retry or universal dry-run/rollback claim.
- Apply bounded automatic retry only to explicitly throttled Cost Management query/forecast reads through the shared coordinator. Honor allowlisted retry headers exposed by CLI, preserve shared pacing/cooldown across Refresh jobs, and never retry mutations. Keep complete billing cache data isolated by CLI configuration, identity, exact scope and basis, with explicit billing freshness. Do not enable debug/verbose output or persist raw diagnostics to discover headers. Test throttling, cancellation, cache isolation and host-relayed retry hints with a fake clock rather than real sleeps.
- Exploration preferences must use the backend JSON store with an explicit bounded projection. Do not access browser storage from iframe source. Run the actual host render-source guard in deployment smoke, not only standalone DOM/browser tests. Deduplicate unchanged preference writes to avoid refresh loops.
- Sanitize errors and store only projected public metadata, plans, views, operations and demo overrides. Never persist raw CLI stdout/stderr, credentials or tokens. Await storage flush before save acknowledgements.
- `npm run verify` runs type checking, native FDO source suites, explicit jsdom journey tests, compilation and actual host startup/deployment transport smoke. Browser smoke additionally verifies real host charts and responsive layout without calling Azure. All generated test files/logs belong in disposable OS temp directories.

Keep forecast remaining-month scope/basis labels and batched selected-group filtering without broader fallback, Azure alert configuration versus plugin anomaly separation, metric sample coverage, deployment/tool/creator evidence, and observed seven-day actual-cost measurement/48-hour lag documented. No undocumented Azure anomaly insight endpoint. No original-creation inference from deployment operations or client signatures.

Service inspection must remain read-only: fixed Databricks collections on the exact ARM-reported public workspace hostname, existing CLI-managed Entra audience, no PAT/token extraction, auto-provisioning, arbitrary SQL or paid-compute starts. The only SQL is a fixed `system.billing.usage` aggregate plus an optional current `list_prices` read, and only after a warehouse id is rechecked as RUNNING. Cancel that statement if it is still running after 50 seconds. Do not follow external result links, select tags, identity or notebook ids, or add list-price estimates to Azure totals. Each usage row is assigned to one object. List vector-search indexes and show each RAG index with its index endpoint. Do not read index contents, schema JSON, or status messages. Review a job definition for deletion only when it is not unpaused, the run list completed, and that window has no runs. Review an IDLE pipeline definition only when its newest returned update is at least 14 days old. Do not treat either card as permission to delete managed VMs or, for a pipeline, its unread target tables. An unpaused job or RUNNING pipeline stays in use. A partial run list is not a zero. SQL history and cluster-event reads must project away statement text and event payloads. A collection that hits its record cap is Partial and a lower bound, never a zero. Keep the 20-cluster event cap, and skip event reads when last activity is already under 24 hours. Coverage failures are classified without storing the provider text. ARM service pages use projected metadata, collection-bound pagination, independent permission coverage and exact IDs. Keep managed-group charges distinct from workspace/DBU costs; never apportion shared Foundry account charges to every deployment/project. Service cleanup cards are instructions, grouped as shutdown review, policy change, definition-only, or in use, until a dedicated dangerous-action adapter exists. Missing collections are unknown, not zero, and a job-owned cluster is not a manual deletion target. Creation, last control-plane modification, cluster last start, last activity, retained history and workload interactions are separate evidence. Age/no writes never imply safe deletion.

Named checks include currency and scope isolation, unknown creation evidence, lock/attachment/delete-option guards, durable proposals, one-time typed confirmation, drift and partial failures, sanitized CLI auth errors, Resource Graph pagination, the complete demo investigation/deletion journey, saved views and stale-response rejection. Add regressions for semantic changes, not mirror tests of static markup.
