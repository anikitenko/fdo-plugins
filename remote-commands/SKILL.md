# Remote Commands development guide

Maintain this plugin using the installed `@anikitenko/fdo-sdk` documentation, especially `docs/SSH_TERMINALS.md`, `docs/FDO_HOST_TERMINAL_X11_HANDOFF.md`, `docs/SECRETS_AND_SSH.md`, `docs/RENDER_RUNTIME_CONTRACT.md`, `docs/SAFE_PLUGIN_AUTHORING.md` and `docs/INJECTED_LIBRARIES.md`.

- `index.ts` owns metadata, capability requests and unknown-input handler boundaries. Instantiate and register the plugin at module scope. Declare `source: index.ts` and `main: dist/index.cjs`. The FDO startup compiler must use the shared CSS-to-style-map loader, as fixed in the sibling host runtime. Do not remove `source` as a workaround: the folder-import flow restores it. Keep missing-style failures as a synchronous, readable UI rather than throwing into the SDK’s generic Invalid render payload fallback.
- `backend.ts` owns profile authorization, lazy persistent storage, short-lived reviews, single-use execution and concurrency control. SSH and storage run only in the plugin backend. Do not log scripts, template values, credentials or output.
- `terminal.ts` owns SDK 1.8.3 interactive sessions and one held raw output packet per view; acknowledge only after emulator consumption. `terminal-ui.ts` is a self-contained serialized callback using the host-owned `window.FDOTerminal` wrapper. Keep keyboard input ephemeral, bound input queues, check session identity before queued writes, preserve exact X11 mode and never downgrade untrusted forwarding. Require explicit interactive and X11 host consent. No local echo, transcript persistence, emulator packages or display/credential discovery belongs in the plugin.
- `live.ts` owns backend-only SDK 1.8.2 status subscriptions, streamed execution handles, view-scoped output cursors, idempotent cancellation and lease cleanup. Consume events and results concurrently; never retry via buffered exec().
- `status.ts` formats fresh/stale/unknown observations in a self-contained callback, including clock-skew and lost-feed cases. Keep status separate from command outcomes.
- `model.ts` defines validated per-VM data, editable examples, placeholder resolution and safe service errors. Submit a whole script in a single SSH request. Preserve shell semantics and host authorization.
- `profiles.ts` formats the SDK 1.8.1 optional SSH metadata for IPv4/IPv6 destinations and projects only public fields into UI responses and session-only review snapshots. Keep profile metadata out of persistent workspace data; never use display values to construct SSH commands. Missing fields must remain explicitly unknown. Reject stale execution reviews when the available endpoint, username, authentication type or enrolled fingerprint changes.
- `render.ts` composes SDK-native static UI and serializes the self-contained iframe callback. Finish styled SDK markup with the same collector’s `renderHTML()`. No browser module imports or backend closures belong in serialized callbacks.
- `ui.ts` owns the iframe state, injected ACE integration, VM/batch switching, serialized persistence requests, native modal reviews, safe text output and explicit user actions. Call documented handlers through `window.createBackendReq('UI_MESSAGE', ...)`. Remote execution must always require a visible resolved script and a separate explicit Execute action.
- `styles.css` imports through FDO’s CSS-to-style-map compiler. Register the complete `styles.shell` entry on the same DOM collector as the render, apply the returned class to the root, and finish with `renderHTML()`. The shell owns scoped descendant/state/media rules, including styles for dynamically created fragments. Do not inject a style element or store CSS in markup attributes. Reuse documented theme variables, Pure CSS and SDK UI components; retain accessible labels, visible focus and reduced-motion rules.
- `scripts/host-tooling.mjs` is local verification tooling that loads the sibling FDO checkout’s real virtual filesystem/CSS compiler and artifact resolver. It does not copy those implementations into the deployed bundle. Override the checkout with `FDO_SOURCE_ROOT`. Do not introduce webpack or a parallel CSS parser.
- Declare `createSSHCapabilityBundle({monitorStatus: true})`; declaration never grants `ssh.status.watch` automatically. Monitor the selected VM, show observation time/freshness, release subscriptions on view closure and invalidate stale status in the UI even if polling stalls. Never derive a connected badge from a command result.
- FDO serializes UI bridge requests. Return a short start acknowledgement and deliver completion/errors through bounded polling; never await the entire execution or cancellation acknowledgement in a UI handler. Test against a serialized bridge.
- Execute only a reviewed script through `ssh.start()`, retain the view-scoped handle in the backend, and render bounded stdout/stderr updates as text. Bind the reviewed timeout/capture budget. Preserve partial output on failures, and replace rather than append the terminal capture. Keep cancellation acknowledgement separate from command outcome; only remoteProcessStopped=true confirms termination. View closure requests cancellation, with a bounded backend lease for lost views.
- Require and await JSON flush before acknowledging persistent saves. Retain drafts after write rejection and offer retry; never send raw disk errors/paths to the view. FDO owns shutdown flush/dispose barriers. Keep host-managed profile and command-access authorization intact; do not describe the old one-line policy form as a current limitation. Never fabricate SDK APIs, bypass host policy, fall back to local SSH or persist credentials.
- `tests/live.test.ts` verifies streaming, cancellation races, bounded polling, status freshness, view isolation/teardown and save acknowledgements. `tests/backend.test.ts` verifies shell semantics, isolation, schema validation and execution authorization. `tests/render.test.ts` verifies SDK composition and emitted CSS without browser dependencies. `tests/terminal.test.ts` verifies PTY output acknowledgements, ephemeral input, exact X11 modes and pending-open cleanup. These four source suites run inside FDO’s native test runner. `tests/ui.integration.ts` exercises the serialized iframe callback with a mocked bridge in an explicit local jsdom suite (`npm run test:dom`); keep this filename outside FDO’s `.test`/`.spec` discovery because packaged hosts do not provide jsdom. `tests/bundle-smoke.cjs` verifies the compiled plugin and real SDK disk persistence with a mocked host service. `npm run verify` runs every suite, including `test:host`, which invokes the actual host workspace runner with an Electron app-path adapter.
- Generate local tooling and compiled tests only in disposable OS temporary directories, cleaned in `finally`. Never emit compiled `.test.*` files under the plugin source tree, including hidden directories: FDO would discover and re-bundle them. Do not reuse the host-reserved `__fdoImportMetaUrl` name in local harness banners.
- `test:deployment` exercises actual startup recompilation over a temporary installed workspace with `source` present. Its bundle smoke sends a PLUGIN_RENDER through the SDK communicator, checks that transport returns valid render/on-load strings and verifies computed shell padding, grid columns, panel spacing and typography. CSS-source and editor-only tests cannot substitute for this deployment-path regression.

The full setup, usage and test scope are documented in `README.md`. No fixture output should appear as an actual remote execution result.
